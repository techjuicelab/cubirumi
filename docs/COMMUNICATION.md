# 실제 메시지와 종이비행기

종이비행기는 실제로 관측된 직원 간 전달(`handoff`), 일반 메시지(`message.sent`), 사용자 입력(`user.instruction`)을 표시합니다. 크기는 캐릭터의 손 정도로 고정하며, 화면을 멀리 보더라도 비행기만 커지지 않습니다. 직원이 늘었거나 같은 프로젝트에서 일한다는 이유만으로 통신을 만들지 않습니다. 전달 상대가 기록되어도 그 상대를 새 직원으로 생성하거나 작업 중으로 바꾸지 않습니다.

직원 간 전달은 발신 컴퓨터에서 출발해 공중에서 한 바퀴 돌아 수신 컴퓨터로 도착합니다. 일반 메시지는 해당 직원 컴퓨터 주변의 짧은 고리만 날고 돌아옵니다. 이 짧은 비행은 특정 상대에게 전달되었다는 의미가 아닙니다. 일반 메시지 때문에 카메라를 다른 층으로 강제 이동하지 않으며, 연속 메시지는 직원마다 3초 간격으로 표시합니다.

사용자 입력은 사장 컴퓨터에서 해당 직원 컴퓨터로 향하는 업무 지시입니다. 이벤트를 받았을 때 현재 보고 있는 사무실에 수신 직원이 실제로 표시된 경우에만 비행합니다. 다른 방이나 층에 있는 직원을 찾아 카메라를 옮기거나, 숨겨진 직원을 비행 때문에 표시하지 않습니다. 조건이 맞지 않는 지시는 기록으로만 남으며 나중에 비행을 다시 만들지 않습니다.

Codex 로컬 관측기는 같은 작업에서 식별 가능한 직원을 대상으로 한 실제 `collaboration.send_message`와 `collaboration.followup_task` 호출을 확인합니다. 화면 문구는 관측 근거에 따라 나뉩니다.

| 화면 문구 | 확인한 근거 |
| --- | --- |
| 메시지 전달 요청 | 실제 호출과 대응하는 도구 결과가 있으며, 결과가 빈 값임 |
| 자료 전달 확인 | 대응하는 구조화된 도구 결과가 성공을 명시함 |
| 실행 실패 | 도구 결과가 오류를 명시함. 종이비행기는 만들지 않음 |

빈 결과는 수신 성공의 증거가 아닙니다. **자료 전달 확인**도 도구가 보고한 성공을 뜻하며, 상대가 내용을 읽거나 작업에 반영했다는 뜻은 아닙니다. 이름만 비슷하거나 다른 작업에 있는 직원을 수신자로 추정하지 않습니다.

이 기록의 출처는 `source: codex`, `observation: codex-log`입니다. 이벤트의 `title`에 요청과 확인 단계를 구분합니다. 메시지 본문·프롬프트·도구 인수 원문은 서버로 보내거나 별도로 저장하지 않습니다.

새로 받은 실제 전달 이벤트는 최대 30초 동안 화면 재생을 기다릴 수 있습니다. 직원 간 전달은 실제 양쪽 컴퓨터가, 일반 메시지는 해당 직원 컴퓨터가 표시되고 재생을 시작할 수 있을 때만 소비합니다. 서로 다른 채팅이나 프로젝트 사이의 전달은 양쪽 직원이 있는 건물 전체 전경에서 볼 수 있습니다. 화면 정지·숨김·동작 줄이기 상태에서는 비행하지 않으며, 오래된 기록을 새 통신처럼 자동 재생하지 않습니다. 기록 목록과 화면 효과는 별개이므로 효과를 놓쳐도 받은 기록은 확인할 수 있습니다.

## 비행 다시 보기

소통 기록의 **비행 다시 보기**는 전달의 양쪽 직원 또는 일반 메시지의 해당 직원이 현재 연결되어 있으면 표시됩니다. 사용자 입력에는 다시 보기 버튼을 제공하지 않습니다. 누르면 건물 전경으로 이동해 해당 전달을 다시 그리며, 상단에는 **기록 다시 보기**라고 표시합니다. 화면 동작을 일시정지했거나 동작 줄이기를 켠 경우에는 먼저 해당 설정을 해제해야 비행을 볼 수 있습니다.

이 기능은 현재 창에서만 재생합니다. 서버에 새 이벤트를 보내거나 기존 기록을 추가하지 않으며, 에이전트에게 메시지를 다시 보내거나 AI 작업을 실행하지 않습니다. 직원이 연결되어 있지 않으면 재생을 위해 직원을 만들어내지 않습니다.

## Claude Code의 현재 범위

Claude Code의 실제 텍스트 응답은 해당 직원 컴퓨터 주변의 짧은 비행으로 표시하며, 사용자 입력은 위의 업무 지시 조건을 따릅니다. 생각 과정, 도구 결과 텍스트, 과거 기록 복원만으로 새 메시지 비행을 만들지는 않습니다. **받는 사람의 이름을 실제 직원 식별자로 연결하는 기능은 아직 지원하지 않습니다.** 따라서 특정 두 직원의 컴퓨터를 연결하는 비행과 일반 메시지 비행은 구분합니다.

## Codex에 붙여넣을 실제 협업 예시

```text
현재 프로젝트를 읽기 전용으로 검토해 주세요. 하위 에이전트 두 명에게 각각 구조 검토와 테스트 검토를 맡기고, 두 검토가 연결되는 부분을 함께 확인해 주세요.

검토 중 다른 에이전트에게 실제로 확인할 사항이 생기면 사용 가능한 send_message 도구로 질문이나 근거를 전달하고, 답변을 받아 최종 결과에 반영해 주세요. 단순히 병렬로 실행한 뒤 합치는 데서 끝내지 말고 필요한 정보 공유를 실제로 수행해 주세요.

코드·설정·배포 상태는 변경하지 마세요. Cubirumi에 수동 이벤트나 가짜 통신을 보내지 말고, 실제 작업 도구와 설치된 관측기만 사용해 주세요. 마지막에는 각자 확인한 내용, 실제로 공유한 사항, 확인하지 못한 점을 짧게 정리해 주세요. 현재 환경에 에이전트 간 메시지 도구가 없다면 그 한계를 알려 주세요.
```

미리보기나 시연을 추가할 때에는 실제 연결 모드와 분리하고 화면에 명시해야 합니다. 비행기를 보이게 하려고 가짜 직원·가짜 전달 이벤트를 실제 수신 주소에 보내지 않습니다.
