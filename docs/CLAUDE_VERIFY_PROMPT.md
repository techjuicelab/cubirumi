# Claude에서 직접 확인할 작업

## 새 사무실과 직원

Claude 앱의 **로컬 Code 탭** 또는 터미널 Claude Code에서 실제 프로젝트로 새 대화를 만들고 다음을 붙여 넣습니다. 첫 작업 기록이 생기면 Agent Office가 발견합니다. 같은 프로젝트는 기존 층 안의 새 사무실, 다른 프로젝트는 새 층입니다. 기록이 없는 빈 대화창과 일반 Chat/Cowork는 관측 대상이 아닙니다.

```text
Agent Office 연결을 실제 작업으로 확인하려고 합니다.
현재 프로젝트의 README와 폴더 구조를 읽기 전용으로 확인하고 세 문장으로 요약해 주세요.
가능하면 하위 에이전트 한 명에게 테스트 구성 확인을 맡겨 주세요.
코드나 설정은 바꾸지 마세요. Agent Office에 시연·수동 이벤트를 직접 보내지 마세요.
설치된 훅과 로컬 관측기가 실제 작업만 전달하도록 두세요.
실제 모델·업무 종료·메시지 전달 여부를 확인할 근거가 없으면 추측하지 마세요.
```

## 실제 사용량

사용량은 위 작업 훅과 별개의 연결입니다. **대화형 터미널 Claude Code**에서 아래 프롬프트로 실제 응답을 한 번 받습니다. 일반 Desktop 대화나 `claude -p` 실행으로 상태줄이 동작한다고 가정하지 않습니다.

```text
도구 실행이나 파일 변경 없이 “사용량 연결 확인 완료” 한 문장만 답해주세요.
```

응답 후 Claude Code의 `/usage`와 사무실의 에너지 패널을 비교합니다. 사무실에 `상태줄 연결 대기`가 남으면 보고 명령이 아직 호출되지 않은 것이고, `공식 사용량 수신 대기`로 바뀌면 상태줄은 호출됐지만 공식 한도 필드가 없는 것입니다. 화면은 수신된 데이터를 5초마다 확인하며, 서비스가 한도를 보내지 않으면 현재 잔여량을 표시할 수 없습니다.

## 연결 문제를 Claude에게 조사시키기

Agent Office 저장소를 프로젝트로 열고 다음을 전달합니다.

```text
이 Agent Office 저장소의 docs/CLAUDE_VERIFY_PROMPT.md, docs/USAGE.md, docs/INTEGRATIONS.md를 읽고 Claude 연결만 진단해 주세요.
현재 실행 환경이 Desktop Code, 터미널 Code, 일반 Chat/Cowork 중 무엇인지 먼저 구분하세요.
GET http://127.0.0.1:4780/api/health 와 /api/state, /api/usage를 읽고 새 대화 기록·훅 수신·상태줄 실행·실제 한도 제공을 각각 확인하세요.
node scripts/install-claude.mjs status로 플러그인과 상태줄 연결을 확인할 수 있습니다.
실제 모델과 한도는 근거가 있을 때만 보고하세요. API 인증정보나 대화 원문을 출력하지 마세요.
운영 API에 검증용 이벤트나 가짜 사용량을 POST하지 마세요. context_window/token 수로 구독 잔여량을 계산하지 마세요.
코드 변경이 필요하면 재현과 원인을 먼저 정리하고, 그래픽·카메라·macOS 앱 파일은 변경하지 마세요.
마지막에는 확인한 사실, 아직 확인하지 못한 항목, 사용자가 Claude에서 해야 할 한 단계만 알려주세요.
```

공식 필드의 제공 조건은 [Claude Code statusline 문서](https://code.claude.com/docs/en/statusline)를 따릅니다. 상태줄 스크립트 재실행은 원격 사용량 재조회 보장이 아닙니다.
