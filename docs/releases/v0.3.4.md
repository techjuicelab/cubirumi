# Cubirumi v0.3.4

Choose whether Cubirumi opens when you log in to your Mac. The macOS app menu now exposes the system login-item setting in English and Korean.

## Launch at Login

- Open **Cubirumi → Launch at Login** to enable or disable automatic launch. New installations leave it **off**.
- Opening or updating the app does not register a login item or change an existing system choice. A disabled item stays disabled.
- The menu follows the actual macOS state. **Launch at Login (Approval Required)** means approval is pending; open **Cubirumi → Login Item Settings…** to check it in System Settings. Clicking the pending item again unregisters it.
- An older `io.cubirumi.login.plist` registration appears as **Launch at Login (Legacy Setup)**. Turn it off from the menu to stop that registration and remove its file after making a backup. Opening or updating the app alone does not remove it.

Company and owner names, local settings, and retained activity records are preserved. The normal local history retention limit still applies as new activity arrives. Other source-server LaunchAgents are managed separately; see the [installation guide](https://github.com/techjuicelab/cubirumi/blob/main/docs/DESKTOP.md).

## Download or update

Download the ZIP for your Mac from [GitHub Releases](https://github.com/techjuicelab/cubirumi/releases/latest):

- **Apple Silicon:** `Cubirumi-0.3.4-macos-arm64.zip`
- **Intel:** `Cubirumi-0.3.4-macos-x64.zip`

Both packages require **macOS 13.5 or later** and include the local runtime; no separate Node.js installation is needed.

Existing public app installations can use **Cubirumi → Check for Updates…** (or **업데이트 확인…** in Korean). The existing Sparkle update feed and signing key are retained. If automatic downloads are enabled, a downloaded update installs when you quit the app with `⌘Q`; closing the window alone leaves the app running. Reopen the app and check **About Cubirumi** for version `0.3.4`.

For a manual replacement, quit the old app before replacing `Cubirumi.app`. This release continues the existing distribution policy without Apple Developer ID signing or notarization.

## Validation

v0.3.3 was withheld after Intel validation exceeded the native test compiler limit. This release allows up to two minutes for cold SDK compilation while retaining all assertions and the existing runtime checks.

Before publication, all **633 tests** passed locally with no failures or skips. The TypeScript/web build, the staged public-file check, and an Apple Silicon release-package build with deep code-signature verification passed. Production dependencies had no reported audit vulnerabilities. Native tests cover default-off behavior, preservation of system choices, approval-pending state, visible failures, and backup/removal of recognized legacy registrations without changing real login items.

Verified on **2026-10-17 (KST)**: the [release workflow](https://github.com/techjuicelab/cubirumi/actions/runs/38977364178) passed **633/633 tests on both architectures**, built and signed both packages, and published all six assets. The [main CI](https://github.com/techjuicelab/cubirumi/actions/runs/38977362043) also passed on macOS and Ubuntu with Node.js 22.18 and 24; Ubuntu skips three macOS-only checks.

All six public assets were downloaded without authentication. SHA-256 checksums, ZIP/feed Ed25519 signatures, app code signatures, architectures, all 19 runtime source files, bilingual native login menus, and the latest update feeds were verified. Neither package includes user data or a bundled launchd registration. The public Apple Silicon runtime passed an isolated empty-data health/asset/shutdown check.

The public Apple Silicon app was installed over v0.3.2 with the previous app and local data backed up. All 145 installed regular files matched the public package, existing native choices and company settings were preserved, all 5,000 previously retained events remained, and persistence was healthy. The new native menu and its System Settings link were checked. Cubirumi was absent from the Mac's Open at Login and Background App Activity lists, and the old login LaunchAgent remained unloaded and absent.

Enabling a real login item, its approval flow, and logout/login execution were not tested. A fresh Mac's Gatekeeper first launch, a graphical Sparkle upgrade, and graphical operation on physical Intel hardware were not checked in this release validation.

## 한국어 안내

macOS 상단 **Cubirumi → 로그인 시 실행**에서 로그인 자동 실행을 켜거나 끌 수 있습니다. 신규 설치는 **꺼짐**이며, 앱 실행이나 업데이트가 자동으로 등록하거나 기존 macOS 선택을 바꾸지 않습니다. 꺼 둔 자동 실행을 업데이트가 다시 켜지 않습니다.

체크 표시는 실제 macOS 상태를 따릅니다. **로그인 시 실행 (승인 필요)**가 표시되면 **로그인 항목 설정…**에서 시스템 설정을 열어 승인 상태를 확인하세요. 승인 대기 항목을 다시 누르면 등록을 해제합니다. 이전 `io.cubirumi.login.plist`가 있으면 **로그인 시 실행 (기존 설정)**으로 표시되며, 메뉴에서 끄면 실행을 중지하고 등록 파일을 백업한 뒤 제거합니다. 앱 시작이나 업데이트만으로 기존 등록을 바꾸지는 않습니다.

Apple Silicon은 `arm64`, Intel은 `x64` ZIP을 받으세요. macOS 13.5 이상이 필요합니다. 기존 공개 앱은 **Cubirumi → 업데이트 확인…**으로 업데이트하고, 자동 다운로드를 켰다면 `⌘Q`로 종료한 뒤 다시 열어 적용합니다. **Cubirumi에 관하여**에서 `0.3.4`을 확인하세요. 기존 설정·이름·보관 기록은 유지되며, 새 활동이 쌓일 때 적용되는 기존 기록 보관 한도도 같습니다.
