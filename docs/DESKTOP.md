# macOS 독립 사무실 앱

Cubirumi(큐비루미)를 주소창 없는 독립 창으로 띄웁니다. 창 메뉴에서 **항상 위에 표시**를 켜면 다른 앱에서 일하는 동안에도 옆에 놓고 관찰할 수 있습니다. 창 위치·크기와 항상 위 설정을 저장합니다. 창을 닫아도 Dock에서 다시 열 수 있으며, 앱 종료는 `⌘Q`입니다.

## 다운로드판 설치

다운로드판은 macOS **13.5 이상**에서 실행하는 앱입니다. Node.js·사무실 서버·웹 화면·업데이트 구성요소를 `.app` 안에 포함하며, 사용자에게 npm이나 Xcode 설치를 요구하지 않습니다. 3D 화면은 macOS 기본 WebKit으로 표시합니다.

배포 파일은 [techjuicelab/cubirumi의 GitHub Releases](https://github.com/techjuicelab/cubirumi/releases)에서 제공합니다. 신규 Mac의 Gatekeeper 첫 실행과 공개 서버를 통한 실제 제품의 버전 간 업데이트는 아직 별도 검증이 필요합니다.

1. [GitHub Releases](https://github.com/techjuicelab/cubirumi/releases)에서 Mac에 맞는 ZIP을 내려받습니다. Apple Silicon은 `arm64`, Intel Mac은 `x64`입니다.
2. ZIP을 풀고 `Cubirumi.app`을 응용 프로그램 폴더에 옮긴 뒤 실행합니다.
3. macOS가 개발자를 확인할 수 없다며 실행을 막으면, 내려받은 출처를 확인한 뒤 **시스템 설정 → 개인정보 보호 및 보안 → 보안 → 그래도 열기(Open Anyway)**를 선택합니다. 인증과 확인 창이 나타나면 해당 앱의 실행을 승인합니다. [Apple의 공식 실행 안내](https://support.apple.com/guide/mac-help/open-a-mac-app-from-an-unknown-developer-mh40616/mac)

현재 배포 정책은 Developer ID 서명·Apple 공증 없이 GitHub에서 배포하는 방식입니다. 앱의 임시 서명과 Sparkle 업데이트 서명은 Apple의 개발자 확인·공증을 대신하지 않습니다. 시스템이 파일 손상이나 악성 소프트웨어를 알린다면 실행 허용을 반복하지 말고 배포 파일을 확인하세요.

앱을 열면 자체 사무실 서버를 시작하고, `⌘Q`로 종료하면 자신이 시작한 서버와 관측기를 함께 정리합니다. 창만 닫으면 앱은 계속 실행됩니다. 앱 종료나 업데이트가 원래 Codex·Claude 작업을 종료하지는 않습니다.

## 다운로드판에서 Claude Code 연결

앱을 `/Applications/Cubirumi.app`에 옮겨 첫 실행을 마친 뒤, 평소 Claude Code를 사용하는 터미널에서 실행합니다. 사용자 전용 응용 프로그램 폴더에 설치했다면 첫 줄을 `cubirumi_app="$HOME/Applications/Cubirumi.app"`로 바꿉니다. 아래 명령은 앱 안의 Node.js를 사용하므로 별도 Node.js·npm·저장소가 필요하지 않습니다. 연결 대상인 Claude Code CLI는 설치되어 있고 같은 터미널에서 `claude` 명령으로 실행할 수 있어야 합니다.

```sh
cubirumi_app="/Applications/Cubirumi.app"
"$cubirumi_app/Contents/Helpers/node" "$cubirumi_app/Contents/Resources/runtime/scripts/install-claude.mjs" install
"$cubirumi_app/Contents/Helpers/node" "$cubirumi_app/Contents/Resources/runtime/scripts/install-claude.mjs" status
```

설치기는 사용자 데이터 폴더의 `claude-integration/`에 관리용 플러그인 복사본을 만들고, 각 hook도 앱의 내장 Node.js로 실행하도록 연결합니다. 앱 번들은 수정하지 않습니다. `claude`의 공식 plugin 명령으로 사용자 범위에 등록하며, 기존 표시줄과 다른 설정을 보존하고 `claude-backups/`에 백업합니다. 호환용 플러그인 ID는 `agent-office@agent-office-local`입니다.

연결 후 앱을 옮기거나 이름을 바꾸면 저장된 Node.js·표시줄 경로가 달라집니다. 설치한 위치를 유지하세요. 다른 출처의 같은 이름 marketplace나 기존 소스 설치의 표시줄이 있으면 설치기는 덮어쓰지 않고 중단하므로 기존 연결 경로를 먼저 확인해야 합니다. 업데이트도 같은 설치 위치를 유지합니다.

`status`는 등록된 설정을 확인하는 명령이며 실제 이벤트나 사용 한도를 검증하지 않습니다. 새 Claude Code 세션을 열어 [실제 연결 확인](CLAUDE_VERIFY_PROMPT.md)을 진행하세요. Desktop의 로컬 Code 세션과 터미널의 사용량 보고 범위는 [Claude 연결 안내](CLAUDE_SETUP_PROMPT.md)에 있습니다. 일반 Chat/Cowork는 이 연결 대상이 아닙니다.

## 업데이트와 설정 보존

공개 저장소·공개키가 설정된 배포판은 Sparkle로 새 버전을 확인합니다. **자동 확인과 자동 다운로드가 기본값**이며, 준비된 업데이트는 앱을 종료할 때 적용합니다. 메뉴에서 다음 설정을 바꿀 수 있고 선택은 다음 실행에도 유지됩니다.

| 앱 메뉴 | 기능 |
| --- | --- |
| 업데이트 확인… | 새 버전을 직접 확인 |
| 자동으로 업데이트 확인 | 정기 확인 켜기·끄기 |
| 업데이트 자동 다운로드 및 종료 시 설치 | 미리 내려받고 종료 시 적용하는 동작 켜기·끄기 |

업데이트 연결이 설정되지 않은 로컬 검증용 빌드와 개발용 창에서는 이 메뉴가 비활성화됩니다. 업데이트 파일의 서명이 맞지 않으면 설치하지 않습니다. 설치 위치의 권한이나 macOS 보안 확인에 따라 추가 확인이 필요할 수 있어 모든 환경에서 무인 설치를 보장하지는 않습니다. [Sparkle의 업데이트 동작](https://sparkle-project.org/documentation/gentle-reminders/)

회사명·사장 이름과 관측 기록은 앱 번들 밖의 `~/Library/Application Support/AgentOffice`에 저장합니다. 다운로드판 업데이트는 이 사용자 데이터 폴더를 교체하거나 삭제하지 않습니다. 창 설정과 업데이트 선택도 앱 버전과 별도로 보관합니다.

## 기존 소스 설치에서 전환

다운로드판과 소스에서 실행한 `npm start` 또는 기존 LaunchAgent는 같은 `4780` 포트를 사용합니다. 먼저 기존 방식의 서버를 중지하고 다운로드판을 여세요. 포트를 다른 서버가 쓰고 있으면 다운로드판은 충돌을 안내하며 그 서버를 임의로 종료하지 않습니다.

터미널에서 직접 실행한 서버는 해당 터미널의 `Ctrl+C`로 중지합니다. 소스 자동 실행을 등록했다면 기존 저장소에서 상태를 확인하고 현재 로그인 세션의 서비스를 중지할 수 있습니다.

```sh
node scripts/install-runtime.mjs status
node scripts/install-runtime.mjs stop
```

`stop`은 자동 실행 등록 파일을 삭제하지 않습니다. 다음 로그인 때 다시 시작될 수 있으므로 기존 LaunchAgent가 남아 있는 상태를 영구 이전 완료로 취급하지 않습니다. 같은 사용자 데이터 폴더를 사용하는 경우 이름과 기록을 다시 입력할 필요는 없습니다. 별도 데이터 경로를 사용했던 설치는 그 경로도 함께 유지해야 합니다.

## 소스 개발용 창

아래 방식은 별도 로컬 서버에 연결하는 개발용 창입니다. 기존 개발 설치와의 호환을 위해 이 창의 파일 이름은 `Agent Office.app`을 유지합니다. 빌드에는 Node.js **22.18 이상**, npm과 Xcode 또는 Swift 컴파일러가 포함된 Command Line Tools가 필요합니다. 저장소 폴더에서 실행합니다.

```sh
npm ci
npm run build
node scripts/install-runtime.mjs install
npm run desktop:install
open "$HOME/Applications/Agent Office.app"
```

이 방식의 수신기는 로그인 시 실행되고, 창은 `127.0.0.1:4780`에 연결합니다. 개발용 창만 다른 컴퓨터로 복사하면 수신기가 설치되는 것은 아닙니다. 저장소나 Node.js를 옮기려면 기존 위치에서 서비스를 제거한 뒤 새 위치에서 설치하세요. `stop`만으로 자동 실행 등록 파일까지 제거되지는 않습니다. 서버 연결이 끊어지면 창이 재연결을 기다립니다.

개발용 창을 빌드만 하려면 `npm run desktop:build`를 사용합니다. 결과는 `artifacts/Agent Office.app`입니다. `desktop:install`은 bundle ID를 확인하고 기존 앱을 개인 데이터 폴더에 백업한 뒤 설치합니다. Node.js·서버를 포함하는 ZIP은 별도 명령 `npm run desktop:package`로 만듭니다. 빌드 결과와 업데이트 서명 절차는 [릴리스 안내](RELEASING.md)에 있습니다.

## 사무실 조작

앱 내부는 로컬 사무실만 표시합니다. 사용자가 누른 Claude 공식 사용량 링크는 기본 브라우저에서 열며, 웹 페이지에 셸 실행 권한을 제공하지 않습니다.

연결된 프로젝트마다 건물의 한 층을 사용합니다. 층을 선택하면 같은 프로젝트의 여러 채팅에 연결된 직원을 함께 보여주며, 채팅 선택창에서 특정 채팅으로 좁혀볼 수 있습니다. 현재 활동 인원이 바뀌면 층과 실내의 바닥·책상 배치도 늘거나 줄어듭니다. 대기 직원의 기록은 전체 직원 목록에 보관하며 상시 좌석을 차지하지 않습니다. 활동이 없는 프로젝트는 작은 빈 층으로 남습니다. 실제로 연결된 직원이 없는 프로젝트는 층으로 만들지 않습니다.

앱을 열거나 새로고침하면 수동으로 둘러보는 화면으로 시작합니다. **자동 관찰** 또는 `C`를 눌렀을 때만 자동 회전·업무 추적·사무실 순회가 실행됩니다. 관찰을 시작하면 수동으로 선택했던 층과 관계없이 현재 활동이 있는 층·작업구역을 둘러봅니다. 활동이 있는 층이 하나면 실내로 바로 이동하며, 여러 층을 오갈 때 건물 전경을 보여줍니다. 건물의 층 명찰과 왼쪽 층 목록에서 프로젝트를 선택할 수 있습니다. 상단의 관찰 장소 표시는 건물 전체를 보는지, 어느 프로젝트와 채팅을 보는지 알려줍니다.

| 조작 | 동작 |
| --- | --- |
| 층·직원 선택 | 자동 관찰을 종료하고 선택한 층이나 직원을 가까이에서 보기 |
| 건물 전체 보기 / `⌘0` | 자동 관찰을 종료하고 전체 건물 전경으로 이동 |
| 다른 앱으로 포커스 이동·복귀 | 선택한 화면과 자동 관찰 상태 유지 |
| 자동 관찰 버튼 / `C` | 자동 관찰 시작·종료 |
| `Esc` | 자동 관찰 종료 및 메뉴 표시 |
| 좌우 드래그 / `←`·`→` | 카메라를 건물이나 사무실 둘레로 회전 |
| 위아래 드래그 / `↑`·`↓` | 카메라의 내려다보는 각도 조절 |
| 휠·트랙패드 핀치 / `+`·`-` | 확대·축소 |
| 우클릭 드래그 / `Shift` 드래그 | 화면에서 관찰 중심 이동 |
| `Home` | 기본 카메라 시점으로 복귀 |
| `⌘T` | 항상 위에 표시 전환 |
| `⌘R` | 최신 사무실 화면 다시 열기 |
| `⌘A` · `⌘C` · `⌘V` · `⌘X` | 입력창의 전체 선택 · 복사 · 붙여넣기 · 잘라내기 |
| `⌘Z` · `⇧⌘Z` | 입력한 내용 실행 취소 · 다시 실행 |

방향키와 `Home`은 3D 화면에 키보드 초점이 있을 때 사용합니다. 직접 확대·축소·회전·이동하거나 기본 시점으로 돌아가면 자동 관찰이 종료됩니다. 선택한 화면은 시간이 지나거나 다른 앱에서 작업해도 유지되며, **자동 관찰** 또는 `C`를 다시 눌러야 자동 관찰을 시작합니다. 말풍선과 관찰 중의 자동 회전·업무 추적·순회 간격은 사무실 설정에서 조절합니다. 말풍선은 관측된 업무와 상태를 표현합니다. 내부 사고나 실제 키보드 입력을 표시하지 않습니다.

종이비행기의 전달 요청·확인 구분과 **비행 다시 보기**는 [소통 안내](COMMUNICATION.md)를 참고하세요.

## 앱 아이콘과 보관된 시안

기본 아이콘은 **C · 화이트·스카이블루**의 세 층 회사입니다. macOS 앱은 여러 해상도의 `AppIcon.icns`를 사용하고, 웹의 탭·홈 화면도 같은 원본의 PNG를 사용합니다.

초기 6개 시안과 색상안 A·B·C는 [아이콘 보관함](../design/icons/README.md)에 원본·프롬프트와 함께 보존합니다. B · 네이비·앰버는 향후 다크모드 후보이며 현재 다크모드에 따라 아이콘이 자동 변경되는 기능은 없습니다.

준비된 투명 PNG 원본으로 아이콘 파일을 다시 만들 때는 macOS에서 `npm run icons:build`를 실행합니다. 생성된 ICNS와 웹 PNG도 저장소에 포함하므로 일반 설치에서 다시 생성할 필요는 없습니다. 아이콘 변경 후 `npm run build`와 `npm run desktop:install`을 실행하고 앱을 종료한 뒤 다시 열면 반영됩니다. 원본 디자인을 다듬는 단계와 해상도·ICNS 변환 단계는 분리되어 있습니다.

## 활동 목록과 사용량

하단 활동 배지는 작업·승인·오류 상태의 직원 수입니다. 직원 패널은 활동 중인 직원을 먼저 보여주며, 전체 직원에서 대기 중인 직원도 확인할 수 있습니다. 승인·오류가 있는 층은 확인 필요 인원을 따로 표시하고 활동 있는 곳 버튼으로 이동할 수 있습니다.

사용량 카드의 마지막 기록은 현재 값이 아닙니다. Claude 카드를 누르면 Claude 상세로 이동하고, 공식 사용량 열기 링크로 기본 브라우저에서 현재 한도를 확인할 수 있습니다. 수신 내용 새로고침은 로컬 수신 내용을 다시 읽으며 Claude 원격 한도를 직접 조회하지 않습니다.
