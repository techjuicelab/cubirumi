# 업무별 3D 애니메이션

현재 사무실의 캐릭터·가구·배치·색감·조명을 유지하면서, 관측된 업무에 맞는 작은 장치가 모니터 주변에서 움직입니다. 업무 종류는 Codex와 Claude Code에 같은 의미로 적용합니다.

## 업무와 장면

| 업무 종류 | 장면 | 대표적인 분류 근거 |
| --- | --- | --- |
| 코드 작업 | 모니터에서 나온 두 로봇팔이 떠 있는 코드 블록을 조립 | 코드 파일 편집, 코드 파일의 patch |
| 문서 정리 | 빈 종이에 글줄 생성 → 화면 밖으로 출력 → 정렬 → 폴더에 수납 | Markdown·문서 파일 편집 |
| 자료 조사 | 작은 드론이 자료를 들고 오고 주변 카드가 움직임 | 검색·파일 탐색·웹 검색 도구 |
| 테스트·빌드 | 검사대의 탐침과 검사 장치가 작동 | 알려진 테스트·빌드·검사 명령 |
| 검토 | 확대경과 자료를 함께 살펴봄 | 파일 읽기, diff·검토 명령 |
| 계획 정리 | 보드의 작은 카드들을 배열 | 계획·할 일 관리 도구 |
| 디자인 작업 | 캔버스와 붓·색상 조각으로 작업 | 이미지 생성, 디자인 파일 편집 |
| 업무 전달 | 작은 편지와 발송 준비 동작 | 위임·메시지 전달 도구 |
| 결과물 내보내기 | 작은 결과물을 포장하는 장치 | 알려진 배포·발행 명령 |
| 일반 작업 | 작은 공통 작업 소품 | 종류를 확실하게 구분할 수 없는 호출 |

업무 전달 소품은 로컬 업무 동작입니다. 실제 직원 사이의 종이비행기는 기존처럼 발신·수신 관계가 관측됐을 때만 별도로 날아갑니다. 소품의 완성 모양이나 순환 주기는 실제 작업 진행률·성공 여부를 의미하지 않습니다.

## 전환과 상태

- 같은 종류의 작업은 장치를 매번 다시 꺼내지 않고 반복 동작을 이어갑니다.
- 짧게 끼어든 다른 종류는 작은 보조 소품으로 표현합니다. 주 장면은 최소 4초 유지하고, 새로운 종류가 2.6초 이상 이어지면 주 장면을 바꿉니다. 이는 관측된 행동을 묶는 기준이며 전체 업무 의도를 추정하지 않습니다.
- 새 미분류 실행은 일반 작업으로 전환합니다. 이전 코딩 장면을 미확인 작업의 의미로 계속 사용하지 않습니다.
- 응답 종료·대기에서는 소품이 약 0.65초 동안 작아지며 수납됩니다. 전체 업무 성공을 축하하는 연출을 만들지 않습니다.
- 도구 결과를 받아 생각·검토하는 상태에서는 움직임의 강도를 낮춰 주 장면을 이어갑니다. 명시적인 대기·응답 종료·일시정지에서는 멈추고, 오류에서는 장치가 멈추며 오류 표시가 나타납니다.
- 승인 방문과 서류 운반으로 자리를 떠날 때에는 책상의 업무 소품을 숨깁니다.
- 직원 신원이나 업무가 바뀌거나 좌석이 제거되면 이전 소품을 해제합니다.

## 멀리서 보는 직원 표시

작업 중인 직원에게 밝은 코랄 빨강(`#ff5b54`)의 두꺼운 바닥 링과 머리 위 표식을 표시합니다. 오류는 진한 빨강, 승인 대기는 주황입니다. 선택한 직원에는 별도의 바깥 링을 사용해 작업 상태와 선택 상태를 구분합니다.

일반 대기·응답 종료(`idle`, `waiting`, `done`) 직원은 사무실과 건물 보기에서 캐릭터·이름·말풍선·업무 소품을 숨깁니다. 작업·생각·검토가 다시 시작되면 같은 자리에 나타납니다. 승인 대기와 오류는 확인이 필요한 상태이므로 계속 표시합니다.

직원 기록과 책상은 유지합니다. 직원 메뉴에서 이전 상태와 모델을 확인할 수 있고, 관측된 메시지는 해당 모니터에서 계속 표현됩니다. 직원이 쉬거나 복귀할 때 보고 있던 층·채팅·확대 상태와 좌석 배치는 바뀌지 않습니다. 상단 인원은 작업 중·확인 필요·대기로 나누어 표시합니다. 사장 캐릭터는 사무실의 고정 구성원으로 남습니다.

사무실 전체 보기와 건물 전경에도 표시가 남습니다. 건물 전경은 인스턴싱한 작은 업무별 입체 소품을 사용합니다. 가까이 보는 사무실에서는 최대 12명의 세부 소품을 동시에 표시하고, 나머지 작업자는 업무별 입체 표식을 사용합니다. 소품 수 제한 때문에 작업 중인 캐릭터를 숨기거나 관측 인원을 줄이지 않습니다.

## 동작·카메라·개인정보

- 자동 순회는 관찰 모드를 직접 켰을 때만 실행합니다. 수동 확대·층 선택 뒤에는 다른 앱으로 이동해도 화면을 유지합니다. 작은 소품 동작마다 카메라를 이동하지 않습니다.
- 관찰 모드에서도 오른쪽 카메라 도구를 표시합니다. 높낮이·줌·방향 움직임을 켜고 끌 수 있으며, 수동 보기에서는 관찰 모드를 켜야 사용할 수 있다는 설명을 표시합니다.
- 관찰은 선택한 범위에서 작업·생각·검토 중이거나 승인·오류 확인이 필요한 직원만 대상으로 합니다. 대기·응답 종료 직원만 있는 층과 채팅은 순회하지 않습니다. 활성 층이 하나면 그 사무실을 바로 보여주고, 모두 대기하면 카메라도 기다립니다. 관찰이 켜진 상태에서 새 활동이 도착하면 다시 해당 작업을 보여줍니다.
- 무음이며 기존 일시정지·동작 줄이기·절전 설정을 따릅니다. 동작 줄이기에서도 정적인 업무 소품이 보입니다.
- 로컬 관측기는 도구 이름, 파일 확장자, patch의 파일 헤더와 알려진 명령 종류를 확인합니다. 제한적으로 해석할 수 있는 `functions.exec` 내부의 리터럴 도구 호출도 분류합니다. 코드를 실행해서 분류하지 않습니다.
- 동적 변수·템플릿 보간·복잡한 명령·서로 다른 종류가 섞인 호출은 `general`로 단순화합니다.
- 화면·기록으로 전달하는 새 정보는 `activityKind` 열거값입니다. 원문 코드·문서·명령·전체 파일 경로를 새로 저장하거나 외부 AI에 보내지 않습니다.
- 모델 정보 보정은 업무 종류를 바꾸지 않습니다. 이전 플러그인의 분류 없는 기록은 임의로 상세 업무로 바꾸지 않습니다.

## 검증과 실행

`npm test`는 분류 → 이벤트 검증 → HTTP 수신 → 저장·복원 → 화면 상태·말풍선의 연결과 3D 동작·전환·자원 해제를 검증합니다. `npm run build`로 배포 UI를 만듭니다.

새 관측 분류를 실제 실행에 반영하려면 기존 로컬 runtime을 새 코드로 재시작해야 합니다. 설치형 hook 플러그인은 해당 플러그인의 새 버전으로 갱신해야 합니다. 이미 저장된 과거 기록에는 새 분류 근거를 만들어 넣지 않습니다.

브라우저 시연은 실제 업무와 별개로 확인하며, 시연 이벤트를 실제 직원의 기록으로 전송하지 않습니다. 실제 Codex·Claude 연결은 각 공급자의 새 도구 사용 이벤트로 별도로 확인해야 합니다.
